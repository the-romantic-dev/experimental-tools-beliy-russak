# Гайд по тулкиту

Код лежит в пакете `aic_pipeline`, установленном в среду.
Всё запускается через один вход. Обёртки подставляют нужный интерпретатор,
чтобы не писать путь к conda-среде руками:

| Оболочка | Обёртка | Вызов |
|---|---|---|
| PowerShell | `aic.ps1` | `.\aic.ps1 train -c baseline` |
| cmd.exe | `aic.cmd` | `aic train -c baseline` |
| любая, среда активирована | — | `python cli.py train -c baseline` |
| после `pip install -e .`, из любой папки | — | `aic train -c baseline` |

**В cmd `.\aic.ps1` не работает** — cmd не умеет запускать PowerShell-скрипты и
просто открывает файл в ассоциированном редакторе. Используй `aic` (без `.\`)
или `python cli.py`.

Дальше в гайде команды написаны в форме для PowerShell; в cmd меняй `.\aic.ps1`
на `aic`.

---

## 1. С чего начать

Один раз — PowerShell:

```powershell
.\scripts\setup.ps1
```

или cmd:

```bat
scripts\setup.cmd
```

Скрипт поставит зависимости, проверит среду и GPU, прогонит тесты, соберёт индекс
датасета и фолды, и в конце сделает smoke-прогон. Занимает ~10 минут, из них
почти всё — разовое сканирование 103 тысяч масок.

Потом первый настоящий эксперимент:

```powershell
.\aic.ps1 train -c baseline
```

Если что-то пошло не так — `.\aic.ps1 env` покажет, что видит Python, и чего не хватает.

## 2. Карта проекта

Репозиторий делится надвое: **пакет** — код тулкита, его ставят и импортируют;
**воркспейс** — данные, конфиги и результаты, они у каждого свои.

```
pyproject.toml       метаданные пакета, зависимости, команда `aic`
cli.py               запускатель из корня: зовёт CLI пакета
aic.ps1              обёртка для PowerShell
aic.cmd              обёртка для cmd.exe (ASCII + CRLF — иначе cmd её не разберёт)

aic_pipeline/   ← пакет
  workspace.py       где лежит воркспейс и все пути внутри него
  config.py          загрузка конфигов, наследование, переопределения из CLI
  indexing.py        train.csv -> artifacts/index.parquet
  splits.py          групповые стратифицированные фолды
  precache.py        ресайз-кэш датасета
  datasets.py        Dataset, балансирующий сэмплер (негативы + мелкие маски)
  transforms.py      аугментации
  models/            реестр моделей (smp и HF за одним интерфейсом)
  streams.py         SRM/Bayar-остаток, вторая ветка и гейт-фьюз
  losses.py          BCE / Dice / Focal / Tversky + aux-классификация
  metrics.py         AIC Score и перебор порогов
  engine.py          циклы train/validate, оптимизатор, планировщик
  train.py           оркестрация одного эксперимента
  plans.py           очередь экспериментов: раскрытие плана, префлайт, прогон
  inference.py       предсказание, TTA, возврат в исходное разрешение
  calibrate.py       подбор порогов по сохранённой статистике
  submission.py      сборка и проверка сабмита
  cli.py             все команды
  analysis/          profile_data.py, leaderboard.py, viz.py, oof_report.py,
                     compare_runs.py

configs/             конфиги экспериментов (YAML с наследованием)   ← воркспейс
plans/               очереди экспериментов: несколько прогонов одним запуском
tests/               221 тест, гоняются за 15 секунд
runs/                результаты прогонов
artifacts/           index.parquet, folds.parquet
data/cache/          ресайз-кэш (создаётся по запросу)
aic_plugins.py       свои компоненты (необязателен, см. docs/EXTENDING.md)
```

В репозитории из воркспейса лежат только примеры: `_base.yaml`, `smoke`,
`baseline`, пара рецептов моделей и `plans/example.yaml`. Рабочие гипотезы,
данные и прогоны у каждого свои и не коммитятся.

### Установка и импорт

```powershell
D:/Apps/anaconda3/envs/challenges/python.exe -m pip install -r requirements.txt
```

Ставит пакет в editable-режиме вместе с зависимостями: правки в коде видны

Из Python пакет зовут так:

```python

cfg = aic_pipeline.load_config("baseline", ["train.lr=1e-4"])
board = aic_pipeline.leaderboard()
```

### Где тулкит ищет данные

Пакет установлен один, а воркспейсов может быть несколько — например, у
соседней задачи свои `data/` и `runs/`. Корень определяется в таком порядке,
побеждает первое сработавшее:

1. явный вызов `aic_pipeline.set_workspace("D:/projects/другая-задача")`;
2. переменная среды `AIC_WORKSPACE`;
3. ближайшая вверх от текущей папки директория, в которой есть `configs/`;
4. текущая папка.

Пункт 3 покрывает обычную работу: и из корня репозитория, и из `notebooks/`
находится один и тот же воркспейс, ничего настраивать не надо. Какой корень
выбран сейчас, показывает `.\aic.ps1 env` первой же строкой.

Временно переключиться, не трогая глобальное состояние:

```python
from aic_pipeline.workspace import use_workspace

with use_workspace("D:/projects/другая-задача"):
    board = aic_pipeline.leaderboard()
```

изображение, маска. После группировки по исходному кадру остаётся 79 416 групп:
часть доменов переиспользует один кадр до 15 раз.

| Домен | Строк | Групп | Негативов | Что это |
|---|---|---|---|---|
| `plain` | 35 536 | 35 536 | 3 118 | числовые имена; здесь почти все негативы |
| `coco` | 33 483 | 33 483 | 0 | COCO + инпейнтинг |
| `vision` | 13 255 | 900 | 54 | камерные снимки `D01…D44`, по 15 правок на кадр |
| `raise` | 11 802 | 6 093 | 0 | RAISE |
| `numid` | 6 669 | 450 | 15 | числовой префикс + размер правки |
| `openimages` | 2 954 | 2 954 | 0 | Open Images |

| Генератор | Строк | Медианная площадь маски |
|---|---|---|
| `none` (без манипуляции или без метки) | 35 536 | 0.113 |
| `inpainted` | 19 924 | 0.188 |
| `removeanything` | 14 875 | 0.146 |
| `inpaintanything` | 13 502 | 0.166 |
| `brushnet` | 7 111 | 0.161 |
| `powerpaint` | 6 763 | 0.165 |
| `hdpainter` | 5 988 | 0.157 |

Негативов всего 3 187 — **3.1%** от датасета. При этом они дают половину метрики.

Три вещи, про которые легко забыть:

1. **Маски не бинарные.** В PNG встречаются значения 0…255 (мягкие края).
   Везде бинаризуем по 128; в обучении за это отвечает `data.gt_binarize`.
2. **Негативы уже есть в трейне** — кадры с полностью пустой маской, 3.1% строк.
   Именно они дают `FPR_neg`, то есть половину метрики. Плюс есть 42 530 чистых
   оригиналов в `src`, которых можно добрать через `data.extra_negatives`.
3. **Один оригинал = несколько строк.** В `vision` — до 15 манипуляций одного
   кадра. Без группового сплита валидация врёт.
4. **Имена файлов — источник разметки по доменам и генераторам.** Разбор живёт в
   `aic/data.py`. Если появится новый формат
   имён, его надо туда добавить, иначе кадры разъедутся по фолдам (проверка на
   утечку это поймает).

### Индекс

```powershell
.\aic.ps1 index
```

Разово читает все маски и складывает `artifacts/index.parquet`: домен,
генератор, `group_id`, площадь маски, разрешение, флаг негатива. Дальше всё
работает с этой таблицей, а не с CSV.

Посмотреть, что получилось:

```powershell
.\aic.ps1 profile
```

### Фолды

```powershell
.\aic.ps1 split --folds 5
```

`StratifiedGroupKFold` по `group_id`, страта = домен × генератор × признак
негатива × корзина по площади. Команда сама печатает проверку на утечку —
там должно быть `0`. Если не ноль, дальше идти нельзя: валидация не отражает тест.

### Ресайз-кэш

```powershell
.\aic.ps1 precache --max-side 768
```

Ужимает датасет до 768 px по длинной стороне и ставится в конфиг как
`data.source: cache`. Лежит в `data/cache/s768/`, структура путей повторяет
исходную. Шаг возобновляемый: уже готовые файлы пропускаются.

**Насколько это окупается — замеры, а не ощущения.** Исходники уже ограничены
1024 px (медиана длинной стороны ровно 1024, крупнее нет вообще), поэтому при
`max_side=768` ресайзятся только 55.5% файлов, остальные копируются байт в байт.

| | Значение |
|---|---|
| Размер кэша s768 | ~72% от оригинала (36 ГБ → ~26 ГБ) |
| Пикселей меньше | в 1.38 раза |
| Декод быстрее | в 1.38 раза (3.12 → 2.26 мс/файл, 1 поток) |
| То же для s512 | пикселей меньше в 2.14 раза |

Ускорение декода в точности пропорционально числу пикселей — декод упирается
в пиксели, а не в чтение с диска.

**Главное: чаще всего это не узкое место.** На `baseline` (512 px, `bs=8`,
ConvNeXt-Tiny) шаг занимает ~320 мс, а декод батча — это 8 × 3.12 ≈ 25 мс
работы CPU, размазанной по 6 воркерам и полностью спрятанной за счётом на GPU.
Кэш там не даст почти ничего.

Кэш окупается, когда GPU перестаёт быть бутылочным горлышком: маленький вход
(384 px), лёгкий энкодер, большой батч, мало воркеров. Прежде чем его собирать,
посмотри загрузку GPU в `nvidia-smi`: если она стабильно 90%+, узкое место не
в данных и кэш ничего не изменит.

Сторона кэша должна быть **заметно больше** входа модели: при обучении на 512 px
`RandomResizedCrop` берёт кроп и растягивает его до 512, и если кэш тоже 512, то
мелкие кропы будут апскейлиться из ничего. 768 под вход 512 — разумный запас.

Что важно: файлы, которые и так меньше 768, копируются **без перекодирования**.
Повторное JPEG-сжатие затирает ровно те артефакты, по которым ловится подделка,
поэтому и качество по умолчанию 95 — ниже опускать не стоит.

Финальную модель имеет смысл дообучить или хотя бы проверить на `source: raw`.

## 4. Метрика

```
Dice_pos = среднее по позитивам 2|P ∩ G| / (|P| + |G| + 1e-6)
FPR_neg  = доля негативов, где |P| / (H·W) >= 0.01
AIC      = 2 · Dice_pos · (1 − FPR_neg) / (Dice_pos + (1 − FPR_neg))
```

Гармоническое среднее означает, что провал любой половины убивает результат
целиком. `Dice_pos = 0.75` при `FPR_neg = 0.5` даёт `AIC = 0.60`, а
`Dice_pos = 0.65` при `FPR_neg = 0.05` — `0.74`. Второе лучше, хотя сегментация
хуже. Поэтому в логах всегда три числа, а не одно.

Ловушка ложной тревоги грубая: она срабатывает по **площади ≥ 1% кадра**, а не
по факту непустой маски. Немного шума на чистом кадре ничего не стоит, а
уверенное пятно на 2% кадра стоит полного штрафа за этот кадр.

Реализация — `aic/metric.py`, покрыта тестами
(`tests/test_metrics.py`), включая сверку быстрого гистограммного пути с прямым
подсчётом по маскам.

## 5. Конфиги

`configs/_base.yaml` содержит все параметры с комментариями. Остальные конфиги
наследуются от него и переопределяют только то, что действительно меняют:

```yaml
_base_: _base.yaml
name: my-experiment
data: {size: 640}
```

Любой параметр правится из командной строки без редактирования файлов:

```powershell
.\aic.ps1 train -c baseline -s train.lr=1e-4 -s data.size=640 -s data.aug=heavy
```

Значения парсятся как YAML, поэтому `null`, `true`, `[0.5,1.0]` и `3e-4`
приезжают правильными типами.

### Опечатки в именах ключей

Неизвестный ключ раньше проходил молча: `-s train.epohs=20` создавал новый ключ,
а `epochs` оставался прежним — прогон шёл на двенадцати эпохах, и заметить это
было нечем. Теперь такой конфиг не загружается:

```
configs\baseline.yaml: ключи, которых библиотека не знает:
  train.epohs  ->  может быть, train.epochs?
```

Правило простое: ключ, похожий на известный, — ошибка; ключ, ни на что не
похожий, — предупреждение (он ничего не делает, но может быть параметром чужой
компоненты). Полный список ключей с комментариями — `configs/_base.yaml`.

Параметры своих компонент из `aic_plugins.py` клади в секцию с именем самой
компоненты — `train.scheduler: step` открывает `train.step.*`. Проверка узнаёт
такую секцию по значению и внутрь не смотрит. Подробнее —
[docs/EXTENDING.md](docs/EXTENDING.md).

Отключить проверку для одного вызова: `load_config(..., check=False)`.

Готовые конфиги:

| Конфиг | Зачем |
|---|---|
| `smoke` | проверка «пайплайн жив», ~1 минута |
| `baseline` | Unet + ConvNeXt-Tiny, 512 px — точка отсчёта |
| `fast_cache_384` | быстрый цикл для отсева гипотез (треть данных, 384 px) |
| `upernet_convnext_640` | сильнее и тяжелее |
| `segformer_mit_b2` | трансформер, другой профиль ошибок — хорош в ансамбле |

### Свои компоненты

Архитектуры и энкодеры открыты полностью: `model.arch` уходит прямо в

## 6. Цикл эксперимента

```powershell
.\aic.ps1 smoke                            # 1. код не сломан
.\aic.ps1 train -c baseline -s name=exp01   # 2. обучение
.\aic.ps1 calibrate runs/exp01              # 3. подбор порогов
.\aic.ps1 eval runs/exp01                   # 4. честная метрика в полном разрешении
.\aic.ps1 viz runs/exp01                    # 5. посмотреть худшие кадры
.\aic.ps1 board                             # 6. сравнить со всем остальным
```

Всё, что произвёл прогон, лежит в `runs/<name>/`:

| Файл | Что это |
|---|---|
| `config.yaml` | снапшот конфига со всеми переопределениями |
| `train.log` | человекочитаемый лог |
| `metrics.jsonl` | построчные метрики, источник правды |
| `metrics.csv` | то же для Excel |
| `tb/` | TensorBoard |
| `ckpt/best.pt` | лучший чекпоинт по AIC |
| `ckpt/last.pt` | последний, для `--resume` |
| `oof/val.npz` | сжатая статистика валидации |
| `calib.json` | подобранные пороги |
| `summary.json` | итог прогона |

Папки не перетираются: при совпадении имени добавляется временной суффикс.

### Сколько будет идти прогон

Бюджет считается так: `train.epochs × data.epoch_size` — это общее число
просмотренных сэмплов. По умолчанию `epoch_size: null`, то есть эпоха равна
всему train (95 403 сэмпла = 11 925 шагов при `bs: 8` ≈ 65 минут на RTX 3070).

`epoch_size` **не урезает данные**. Сэмплирование идёт с возвращением по всему
train, меняется только длина эпохи. Следствия:

* валидация, подсчёт AIC и сохранение `best.pt` происходят чаще;
* косинусное расписание LR пересчитывается под фактический бюджет, поэтому
  короткий прогон получает честно доспавший LR (в отличие от прерванного длинного);
* `train.early_stop` считает эпохи, так что при коротких эпохах его стоит поднять.

| Хочу | Настройки | Сэмплов |
|---|---|---|
| быстрый сигнал, ~40 мин | `epoch_size=12000 epochs=4` | 48k |
| первый baseline, ~2.5 ч | `epoch_size=24000 epochs=8` | 192k |
| ночь | `epoch_size=40000 epochs=10` | 400k |
| максимум | `epoch_size=null epochs=12` | 1.14M |

Не путать с соседними ключами: `data.train_frac` и `data.train_limit` физически
урезают train до подмножества строк (данные реально теряются), а
`train.max_train_steps` обрывает эпоху, но расписание LR остаётся рассчитанным
на полную — это отладочный флаг, не для реальных прогонов.

Продолжить прерванный прогон:

```powershell
.\aic.ps1 train -c baseline --resume runs/exp01/ckpt/last.pt
```

Кривые обучения:

```powershell
.\scripts\tensorboard.ps1
```

## 7. Калибровка порогов

Ключевая экономия времени во всём тулките. Во время валидации сохраняются не
картинки, а гистограммы вероятностей по каждому кадру (`oof/val.npz`). Из них
восстанавливается `|P|` и `|P ∩ G|` для **любого** порога, поэтому перебор сетки
идёт за секунды, без GPU и без повторного прогона модели.

```powershell
.\aic.ps1 calibrate runs/exp01
```

Перебираются три параметра:

- **`mask_threshold`** — порог бинаризации вероятностей.
- **`cls_threshold`** — порог aux-головы «в кадре есть манипуляция». Если
  уверенность ниже, маска обнуляется целиком. Это главный рычаг против `FPR_neg`:
  порог бинаризации на негативы влияет слабо, а обнуление — напрямую.
- **`min_area`** — предсказания меньше этой доли кадра обнуляются. Осмысленно
  только выше 0.01: всё, что ниже, метрика и так не считает ложной тревогой.
  Но осторожно — 3% позитивов имеют маску меньше 1% кадра, и агрессивный
  `min_area` обнулит их Dice в ноль. Перебор это учитывает, потому что считает
  обе половины метрики сразу, но глазами тоже стоит посмотреть.

Посмотреть форму зависимости:

```powershell
.\aic.ps1 curve runs/exp01
```

Пороги из `calib.json` автоматически подхватываются командой `predict`.

## 8. Сабмит

### Формат

По условию нужен `submission.zip` такой структуры:

```
submission.csv        колонки img_path, prediction_path
predictions/*.png     одноканальные PNG, значения строго 0/255,
                      размер совпадает с входным изображением
```

Тестовая выборка — 2 160 изображений в `data/test_stage1/test_stage1/`. Пути
в `test.csv` заданы относительно папки с самим CSV, а `submission.csv` из
комплекта задаёт правило именования `predictions/<stem>_pred.png`. Этот шаблон
переиспользуется как есть — угадывать ничего не надо.

### Сборка

```powershell
.\aic.ps1 submit runs/exp01
```

Одна команда делает всё: прогоняет модель по `test.csv` в его порядке, пишет
маски, собирает `submission.csv`, пакует `submissions/exp01.zip` и сразу
проверяет результат. Пороги берутся из `calib.json` прогона, любой перебивается
флагом (`--thr`, `--cls-thr`, `--min-area`).

Сначала стоит прогнать на восьми картинках — это займёт секунды и покажет, что
пороги и пути в порядке:

```powershell
.\aic.ps1 submit runs/exp01 --limit 8 --name probe
```

TTA даёт небольшой, но стабильный прирост ценой кратного времени:

```powershell
.\aic.ps1 submit runs/exp01 --tta none,hflip,vflip,hvflip
```

### Ансамбль

Несколько прогонов передаются позиционно, вероятности усредняются **до**
бинаризации (усреднять готовые бинарные маски заметно хуже):

```powershell
.\aic.ps1 submit runs/fold0 runs/fold1 runs/fold2 --name ens3 --thr 0.45
```

Модели должны быть обучены на одном входе (`data.size`, `data.val_mode`) —
иначе команда откажется работать с внятным сообщением. Пороги для ансамбля
задавай явно: усреднение вероятностей меняет калибровку, и `calib.json`
отдельных моделей к нему уже не относится. Без явного `--thr` берётся среднее
по прогонам и печатается предупреждение.

### Проверка

```powershell
.\aic.ps1 check-submission submissions/exp01.zip
```

Работает и с папкой, и с архивом. Проверяет: есть ли `submission.csv` в корне,
те ли колонки, совпадает ли состав с `test.csv`, нет ли дубликатов, лежат ли на
месте все файлы масок, PNG ли это, одноканальные ли, только ли 0 и 255 внутри,
совпадает ли размер каждой маски с её изображением.

Всё это ловится до загрузки — иначе выяснится уже после того, как попытка
потрачена.

### На что смотреть в статистике

`submit` и `check-submission` печатают три числа, которые стоят внимания:

| Поле | Что означает |
|---|---|
| `empty_share` | доля кадров с пустой маской |
| `flagged_share` | доля кадров, где площадь ≥ 1% — **ровно те, что засчитаются как ложная тревога**, если кадр окажется чистым |
| `area_median_nonempty` | медианная площадь непустых масок; в трейне медиана ~0.15 |

Если `flagged_share` близка к единице, модель размечает почти всё подряд и
`FPR_neg` утопит метрику. Лечится подъёмом `cls_thr`. При `flagged_share > 0.9`
команда предупреждает об этом сама.

### Перед отправкой

Сверься с `eval`: во время обучения метрика считается на сетке модели (512×512),
а реальная — на исходном разрешении. Числа расходятся, особенно на мелких масках.

## 10. Что крутить в первую очередь

Примерно в порядке ожидаемой отдачи:

1. **Баланс негативов** — `data.negative_fraction`, `data.extra_negatives`,
   `loss.cls_weight`. Половина метрики держится на них, а негативов в данных ~6%.
2. **Разрешение входа** — `data.size`. Правки бывают мелкими, и на 384 px они
   просто исчезают. 512 → 640 обычно заметно двигает Dice.
3. **Энкодер** — `model.encoder`: `tu-convnext_tiny` → `tu-convnext_small`,
   `tu-tf_efficientnetv2_s`, `tu-mit_b2`.
4. **Состав лосса** — `loss.seg`. Tversky с `alpha < beta` тянет к полноте,
   с `alpha > beta` — к точности, а точность здесь дешевле.
5. **Аугментации** — `data.aug`. Начни с `medium`; `heavy` полезен, если
   валидация заметно лучше теста.
6. **Ансамбль** — несколько фолдов и/или свёрточная модель плюс трансформер.
   Усреднять надо вероятности до бинаризации, и калибровать пороги заново.

Гипотезы дешевле проверять на `fast_cache_384`, а подтверждать на `baseline`.
Сравнивать абсолютные числа между разными конфигами данных нельзя — только
внутри одного.

## 11. Серия экспериментов

Прогон идёт часами, а гипотез за раз проверяется несколько. Ставить их руками
по одной значит либо сидеть у машины, либо терять ночь между прогонами. Очередь
описывается одним YAML в `plans/` и запускается разом:

```powershell
.ic.ps1 plan example --dry-run   # посмотреть, что будет запущено
.ic.ps1 plan example             # пройти очередь до конца
```

Три свойства, ради которых это не цикл в shell:

* **Префлайт.** Перед стартом каждый конфиг загружается и каждая модель
  собирается на CPU со случайными весами. Опечатка в имени энкодера в пятом
  прогоне вылезает сразу, а не через четыре часа. Отдельно — `--check`.
* **Падение не роняет очередь.** Упавший прогон помечается `failed`, остальные
  считаются дальше. Обратное поведение — `--stop-on-error`.
* **Возобновление.** Прогон с готовым `runs/<имя>/summary.json` пропускается,
  поэтому после сбоя план просто запускается заново и доделывает остаток.
  Пересчитать всё принудительно — `--force`.

Итог очереди печатается таблицей и дублируется в `runs/_plan_<имя>.json`.

Формат плана — [plans/example.yaml](plans/example.yaml):

```yaml
name: моя-серия            # префикс имён прогонов
defaults:                  # переопределения для всей очереди
  train.epochs: 6
runs:
  - config: baseline       # имя прогона берётся из самого конфига
  - config: baseline
    name: baseline-768     # или задаётся явно
    set:
      data.size: 768
  - config: baseline       # grid раскрывается в декартово произведение,
    name: sweep-lr         # имена собираются из значений сетки
    grid:
      train.lr: [1.0e-4, 3.0e-4, 1.0e-3]
```

Порядок в очереди сохраняется, поэтому опорный прогон ставь первым. Имена
проверяются на уникальность при загрузке: два прогона с одним именем затёрли
бы результаты друг друга, и план до запуска не дойдёт.

Запустить из плана что-то одно:

```powershell
.ic.ps1 plan example --only baseline-768
```

Свои серии держи в собственном `plans/`: в репозитории лежит только пример,
рабочие очереди у каждого свои и не коммитятся.

Первый шаг прогона на 512+ px занимает **минуты**: `cudnn.benchmark = True`
подбирает алгоритмы под каждую новую форму входа, а у ConvNeXt depthwise 7x7
на большом разрешении тюнится долго. Это разовая плата за прогон, дальше шаги
идут в штатном темпе. Если процесс «завис» сразу после строчки `модель: ...` —
это оно.

### Как читать результат

`board` покажет только итоговый AIC, а гипотезы обычно целятся в разные куски
выборки. Разбор — `report`:

```powershell
.ic.ps1 report runs/моя-гипотеза --vs runs/опорный
```

Он печатает Dice и долю полных промахов по корзинам площади GT, по доменам и
генераторам, плюс потолки. Смотреть надо на корзины, а не на общее число: рост
AIC за счёт крупных масок при просевших мелких означает, что гипотеза не
подтвердилась, даже если число выросло.

### Разделить составляющие гипотезы

Если конфиг меняет сразу несколько вещей и сработал, вклад разделяется
прогонами без правки файла — переопределением по одному фактору:

```powershell
.ic.ps1 train -c мой -s data.small_area_fraction=null -s name=только-лосс
.ic.ps1 train -c мой -s loss.area.small_weight=1.0 -s name=только-сэмплер
```

## 12. Если не хватает памяти GPU

На 8 ГБ порядок действий такой:

1. Уменьшить `train.bs` и поднять `train.accum_steps` — эффективный батч
   останется прежним, а память упадёт.
2. Проверить, что `train.amp: fp16` (по умолчанию так).
3. Уменьшить `data.size`.
4. Взять энкодер полегче.
5. `train.ema: false` — EMA держит вторую копию весов.

Пиковое потребление пишется в лог каждой эпохи (`gpu_gb`).

## 13. Траблшутинг

**`OMP: Error #15` при импорте torch.** В conda-среде две копии OpenMP.
Лечится автоматически: `aic_pipeline/__init__.py` выставляет
`KMP_DUPLICATE_LIB_OK`. Поэтому `import aic_pipeline` обязан
идти **первым** в любом новом скрипте, до torch и numpy. Любой импорт из пакета
проходит через `__init__.py`, так что `from aic_pipeline.train
import run` тоже годится — важно лишь, чтобы это было раньше torch.

**В cmd `.\aic.ps1` открывает файл в редакторе вместо запуска.** cmd не исполняет
`.ps1`. Запускай `aic ...` (обёртка `aic.cmd`) или `python cli.py ...`.

**В PowerShell `.\aic.ps1` ругается на политику выполнения.** Разово:
`powershell -ExecutionPolicy Bypass -File .\aic.ps1 env`, либо один раз для
пользователя: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

**`.ps1` падает с `TerminatorExpectedAtEndOfString` или показывает кракозябры.**
Файл пересохранили без BOM. Windows PowerShell 5.1 читает `.ps1` без BOM как
ANSI, и кириллица в комментариях ломает разбор. Правило для этого проекта:

| Тип файла | Кодировка | Переводы строк |
|---|---|---|
| `.ps1` | UTF-8 **с BOM** | CRLF |
| `.cmd` | **только ASCII** | CRLF |
| `.py`, `.yaml`, `.md` | UTF-8 без BOM | любые |

`.cmd` строго ASCII, потому что cmd.exe читает батник в кодовой странице консоли
(обычно 866) и на не-ASCII комментариях начинает исполнять их куски.

**`нет индекса artifacts/index.parquet`.** Выполни `.\aic.ps1 index`.

**Виснет или падает DataLoader на Windows.** Уменьши `train.num_workers`
(на Windows каждый воркер — отдельный процесс со своим импортом torch).

**Первый запуск долго висит.** Скачиваются предобученные веса энкодера.
Можно проверить пайплайн без сети: `-s model.encoder_weights=null`.

**`утечка групп между фолдами: N` больше нуля.** Разбор имён не покрыл какой-то
новый формат файлов. Смотри `parse_group_id` в
`aic/data.py` и тесты
`tests/test_config_and_parsing.py`.

**AIC на валидации хороший, на лидерборде — нет.** Три обычные причины: метрика
считалась на сетке модели вместо исходного разрешения (проверь через `eval`),
пороги подобраны под один фолд (проверь на других), доля негативов в валидации
не совпадает с тестовой (`FPR_neg` очень чувствителен к этому).

## 14. Справочник по CLI

Общее: `--workers` в `index` и `precache` — это процессы пула для чтения файлов,
а в `eval`/`predict`/`viz` — воркеры DataLoader. `--tta` везде принимает список
через запятую из `none`, `hflip`, `vflip`, `hvflip`.

| `ВИД` | — | показать только один реестр: `loss`, `aug`, `val_mode`, `optimizer`, `scheduler`, `backend` |

### Кривые обучения

Панели `history` по умолчанию: `train/loss+val/loss`, `val/aic_tuned`,
`val/dice_tuned`, `val/fpr_tuned`, `val/best_thr+val/best_cls_thr`, `train/lr`.
Цвет кодирует прогон, тип линии — величину внутри панели.

```powershell
.\aic.ps1 history e0-control-512 e1-res768 e2-area --out runs/_series.png
```

Свой набор панелей:

```powershell
.\aic.ps1 history e0-control-512 e1-res768 --metrics "val/aic_tuned,train/loss+val/loss"
```

Живой вариант с зумом и без пересборки картинки — TensorBoard, все прогоны
пишут в `runs/<имя>/tb/`:

```powershell
tensorboard --logdir runs
```

Что смотреть в первую очередь:

* **`train/loss` против `val/loss`.** Расходятся — переобучение; обе ещё падают —
  бюджет мал, есть смысл докинуть эпох.
* **`val/fpr_tuned`.** Часто именно он держит AIC, а не Dice. Если скачет между
  эпохами — негативов в валидации мало, и порог классификатора подбирается по
  десятку событий.
* **`val/best_thr`.** Гуляет от эпохи к эпохе — значит порог, подобранный на
  последней эпохе, переобучен под фолд и на тесте поедет.
* **`train/lr`.** Проверка, что у сравниваемых прогонов одинаковое расписание:
  кривые обязаны совпасть. Не совпали — бюджеты разные, плечи несравнимы.

Параметры самого обучения (`lr`, `bs`, `size`, состав лосса, аугментации, баланс
негативов) флагами не задаются — они живут в конфиге и правятся через `-s`.
Полный список с комментариями — в [configs/_base.yaml](configs/_base.yaml).
