# Достоверность прироста: статистика в логах прогона

Дата: 2026-08-01

## Задача

Плечи серий e/f/g сравниваются на глаз по одному числу `best_aic`. При этом два
одинаковых прогона на текущем бюджете расходятся на 0.011 AIC, а разброс всех
плеч f-серии уложился в 0.004–0.012. То есть серия из шести прогонов не
измерила ничего, и
понять это можно было только вручную, задним числом, парным бутстрапом по
сохранённым OOF.

Нужно, чтобы прогон сам говорил, чего стоит его результат.

Ключевая ловушка, из-за которой задача не сводится к «добавить доверительный
интервал»: **внутри одного прогона наблюдаем только шум выборки val**
(σ ≈ 0.003). Шум обучения (σ ≈ 0.008 на прогон) внутри прогона не наблюдаем в
принципе — для него нужны реплики с разными сидами. Наивный бутстрап-CI дал бы
для f7 `+0.0118 [+0.0067, +0.0170]` и метку «значимо», хотя ровно такой же
интервал даёт простой повтор с другим сидом.

Решения, принятые до начала работы:

* печатаются **две разные строки** разными механизмами: онлайн-гейт на каждой
  эпохе и финальный вердикт один раз; смешивать их в одну цифру нельзя;
* пол шума обучения задаётся **константой в конфиге** плюс автоматическая
  проверка сопоставимости бюджета с эталоном; автоматический пересчёт по
  репликам не делаем — реплик пока нет;
* гейт **настраиваемый, по умолчанию `warn`**; `stop` включается осознанно для
  ночной очереди;
* гейт судит по **своей** тюненой точке (снисходительно), вердикт — по
  **общей** операционной точке эталона (строго);
* `compare_runs` и `leaderboard` в этот заход не трогаем.

## Измеренная основа

Всё ниже посчитано парным бутстрапом по сохранённым `runs/*/oof/val.npz`,
5025 позитивов и 639 негативов фолда 0.

| пара | что меняется | Δ в своей точке | Δ в точке эталона |
|---|---|---|---|
| f1-seed7 vs f0 (на пересечении val) | только сид обучения | +0.0104 | — |
| e1-res768 vs f0 | «тот же конфиг», разные серии | +0.0122 | +0.0107 |
| f7-aux-all vs f0 | гипотеза | +0.0118 | +0.0068 |
| f6-aux-geom vs f0 | гипотеза | +0.0081 | +0.0049 |
| f5-aux-area vs f0 | гипотеза | +0.0038 | +0.0014 |
| f2-srm-fixed vs f0 | гипотеза | −0.0195 | −0.0227 |

Две пары реплик дают σ разницы 0.0104 и 0.0122, то есть σ одного прогона
0.0074 и 0.0086. Отсюда стартовое значение `train_sigma = 0.008`.

Разрыв между двумя колонками — систематическая накрутка от того, что каждое
плечо подбирает свои `thr/cls/min_area` на одних и тех же 639 негативах. Она
устойчиво положительная и составляет около +0.004.

## Раскладка

Новый модуль `experimental_tools_beliy_russak/stats.py` — чистые функции на
numpy, без torch и без обращения к диску. Это единственная часть, которую надо
покрыть тестами всерьёз, а тестировать её можно только если она не тянет за
собой GPU.

```
per_image(tables, op)                   -> (dice, alarm)
align_by_stem(stems_a, stems_b)         -> (idx_a, idx_b)
paired_bootstrap(a, b, is_pos, n, seed) -> Boot(delta, lo, hi, sd)
verdict(delta, boot, train_sigma)       -> Verdict(label, reason, seeds_needed)
comparable(cfg_a, cfg_b)                -> (bool, list[str])
gate_check(curve_ref, samples, aic, cfg)-> Gate(delta, fired)
```

`tables` — то, что уже отдаёт `AICAccumulator._tables()`; `op` — тройка
`(mask_threshold, cls_threshold, min_area)`.

`load_reference(run_dir)` — единственная функция с I/O: читает `oof/val.npz`,
`oof/val_rows.parquet`, `config.yaml` и `metrics.jsonl` эталона. Лежит там же,
в `stats.py`, но отделена от вычислений.

В `train.py` добавляется два вызова, около 15 строк суммарно: после
`tuned = accumulator.best(...)` (строка 273) и после выхода из цикла эпох
(строка 314).

## Онлайн-гейт

Считается каждую эпоху, если задан `stats.reference`.

Кривая эталона берётся из его `metrics.jsonl` и интерполируется **на то же
число показов**, а не на тот же индекс эпохи: иначе плечо с
`epoch_size: 4000, epochs: 12` нельзя сопоставить с эталоном `8000 × 6`.
Число показов текущей эпохи — `(epoch + 1) * data.epoch_size`.

Сравниваются значения `val/aic_tuned`, то есть каждый прогон в своей тюненой
точке. На ранних эпохах оптимумы порогов сильно разъезжаются (0.375 против
0.2), и общая точка давала бы ложные срабатывания. Гейт нарочно снисходительный:
он ловит только провалы, а не отличает соседние плечи.

Раньше `gate_after_samples` вердикт не выносится вовсе — до этого момента
кривые ещё не расходятся осмысленно.

```
эпоха 3: train_loss=1.1129 val_loss=1.3778 | AIC=0.5970 (...)
  эталон f0-control-768 @24k показов = 0.6563   Δ=-0.0593   ГЕЙТ СРАБОТАЛ (порог -0.05)
```

При `gate_action: stop` прогон прерывается, в `summary.json` пишется
`status: "killed"` с причиной и числом показов, план идёт дальше. При `warn`
печатается та же строка без остановки.

## Финальный вердикт

Считается один раз после цикла эпох.

1. `comparable(cfg, cfg_ref)` сверяет `data.size`, `data.epoch_size`,
   `data.val_frac`, `data.val_seed`, `train.epochs`, `train.bs`,
   `train.accum_steps`, `train.fold`. Расхождение — вердикт не выносится,
   печатается список разошедшихся ключей.
2. Наборы val выравниваются по `stem`.
3. Δ считается в операционной точке **эталона**, парный бутстрап даёт CI.
4. Метка:

```
несопоставимо        -> конфиги разошлись по перечисленным ключам
хуже                 -> Δ < 0 и |Δ| >= 2 * sigma_train * sqrt(2)
подтверждено         -> Δ > 0, |Δ| >= 2 * sigma_train * sqrt(2), CI не накрывает 0
внутри шума обучения -> всё остальное
```

Для метки «внутри шума» считается, сколько сидов на плечо потребовалось бы:
`k = ceil(8 * sigma_train^2 / Δ^2)`, и во сколько часов это встанет при
`2 * k` прогонах. Это и есть главный выход всей затеи: «внутри шума»
превращается в «проверка стоила бы 32 часа, не надо».

```
вердикт против f0-control-768:
  Δ AIC = +0.0068  (в точке эталона thr=0.275 cls=0.5 area=0.000)
  95% CI по выборке val: [+0.0014, +0.0121]   sigma_val = 0.0028
  пол шума обучения: sigma_train = 0.0080 -> sigma разницы 0.0113
  ВНУТРИ ШУМА ОБУЧЕНИЯ: нужно 12 сидов на плечо (24 прогона, ~32 ч)
  справочно, в своей тюненой точке: +0.0118
```

Обе цифры печатаются всегда: разрыв между ними и есть накрутка от подбора
порогов. У f7 это половина видимого «прироста».

## Выравнивание по stem

Пересечение строго по `stem`, никогда по индексу. Если пересечение меньше
набора текущего прогона — предупреждение с числами:

```
ВНИМАНИЕ: val эталона совпадает с текущим только на 1892 из 5664 кадров.
Дельта считается на пересечении (1253 pos / 639 neg), CI будет шире.
```

Это не гипотетический случай: у `f1-seed7` подвыборка позитивов бралась
глобальным сидом, разделение `val_seed` приехало коммитом 29aeb5a уже посреди
его прогона, и с `f0` у него совпадает 1892 строки из 5664. Полсуток выводы
строились на числе, которое мерило шум обучения вперемешку с шумом выборки.

## Конфиг

Новый блок в `_base.yaml`, полностью выключенный по умолчанию:

```yaml
stats:
  reference: null            # имя прогона в runs/; null = вся машинерия выключена
  train_sigma: null          # sigma ОДНОГО прогона, не разницы (см. ниже)
  bootstrap_n: 2000
  bootstrap_seed: 0
  gate_delta: -0.05          # порог отставания от кривой эталона
  gate_after_samples: 24000  # раньше не судим
  gate_action: warn          # warn | stop
```

`train_sigma` — σ **одного прогона**. По паре реплик она равна `|A - B| / sqrt(2)`,
по трём и более — обычное стандартное отклонение. σ разницы двух прогонов
выводится как `train_sigma * sqrt(2)`. Определение обязано стоять комментарием
рядом с ключом: если туда впишут 0.011 (σ разницы), все вердикты поедут в
полтора раза.

Ключи регистрируются в `schema.py`, иначе проверка опечаток в конфиге будет
ругаться на весь блок.

## Стоимость и артефакты

Бутстрап 2000 реплик считается блоками по 250, индексы `int32`: около 10 МБ
пика и порядка секунды на эпоху против 690 с самой эпохи. Новых зависимостей
нет — numpy и pandas уже в проекте.

В `metrics.jsonl` добавляются `ref/aic_at_samples`, `ref/delta`, `ref/gate`.
В `summary.json` — блок `verdict` целиком. При `stats.reference: null` ни одно
из этих полей не появляется.

## Проверка

Всё на CPU, обучение не запускается:

* бутстрап на синтетике с заданным Δ — истина попадает в CI примерно в 95%
  повторов;
* `align_by_stem` на кейсе f1 (разные наборы) — правильное пересечение и
  предупреждение;
* `verdict` при Δ = 0.005 и `train_sigma` = 0.008 → «внутри шума»,
  `seeds_needed` = 21;
* `verdict` при Δ = 0.05 → «подтверждено»; при Δ = −0.05 → «хуже»;
* гейт не срабатывает до `gate_after_samples` и срабатывает после при
  отставании ниже `gate_delta`;
* `comparable` ловит расхождение по `epoch_size`;
* `stats.reference: null` → ни одного лишнего поля в `metrics.jsonl`.

## Что не входит

* колонка вердикта в `compare_runs` и `leaderboard`;
* автоматический пересчёт `train_sigma` по репликам в `runs/`;
* раннер, который сам запускает несколько сидов на плечо.

Всё это осмысленно, но отдельными заходами.

## Порядок работ

1. `stats.py`: `per_image`, `align_by_stem`, `paired_bootstrap` + тесты.
2. `verdict`, `comparable`, `gate_check` + тесты.
3. `load_reference`.
4. Блок `stats` в `_base.yaml` и `schema.py`.
5. Врезка в `train.py`: гейт по эпохам, вердикт после цикла.
6. Тест обратной совместимости: `reference: null` ничего не меняет.
