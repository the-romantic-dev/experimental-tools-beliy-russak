# Свип по сидам: подтверждение прироста f7-aux-all

Дата: 2026-08-01

## Задача

Одиночный прогон `f7-aux-all` дал **+0.0068 AIC** против контроля в его
операционной точке. Это меньше, чем расходятся два одинаковых прогона: пары
реплик дают 0.0104 и 0.0122, то есть sigma одного прогона около 0.008. По
одному прогону на плечо такой эффект неотличим от везения с сидом.

Свип отвечает на один вопрос: **есть ли эффект вообще**. 12 пар «контроль плюс
плечо» с разными сидами, парное сравнение внутри каждой пары.

## Честная оценка шансов

Правило «2 sigma» даёт 12 пар — это то, что печатает `stats.seeds_needed`. Но
оно отвечает на вопрос при мощности 50%: оценка станет двухсигмовой, только
если ляжет ровно на истинное значение, а вбок она уезжает в половине случаев.

Проверка на синтетике с истинным эффектом ровно 0.0068 и sd по парам 0.011 даёт
на 12 парах `t(11) = 2.14, p = 0.055` — то есть впритык мимо порога.

| пар | прогонов | время (обе машины) | шанс поймать эффект 0.0068 |
|---|---|---|---|
| 12 | 24 | ~32 ч, по 16 ч на машину | ~50% |
| 21 | 42 | ~57 ч, по 28 ч на машину | ~80% |

Стартуем с 12: если истинный эффект окажется крупнее ожидаемого, хватит и их.
Сиды на вторую партию зарезервированы (107–112 локально, 207–212 на сервере) —
конфиги и планы для неё делаются копированием с заменой номеров.

Оговорка про добор: если добирать вторую партию, посмотрев на первую, итоговый
p-value становится оптимистичным. Практическое правило — читать результат по
24 парам как alpha около 0.08, а не 0.05. Для инженерного решения это терпимо;
знать об этом надо.

## Решающее правило, зафиксированное ДО запуска

Записано здесь, чтобы потом не подгонять критерий под полученные числа.

* Мера — разница AIC между плечом и контролем **в одной и той же операционной
  точке** `thr=0.275, cls=0.5, min_area=0.0`. Это оптимум старого
  `f0-control-768`, зафиксированный до свипа и не зависящий ни от одного его
  прогона.
* Сравниваются только прогоны с **одинаковым сидом**; статистика считается по
  12 парным разницам, парный t-тест, alpha = 0.05.
* **Подтверждено**, если 95% CI средней разницы не накрывает ноль сверху.
  Иначе — не подтверждено, и головы из финальной модели выбрасываются.
* Тюненые `best_aic` идут в отчёт только справочно. На f7 подбор порогов под
  639 негативов накрутил +0.0050 из видимых +0.0118; решать по этому числу
  нельзя.

## Почему половины устроены именно так

**Оба плеча считаются на обеих машинах.** Соблазн отдать контроль локальной
машине, а плечо серверу, портит весь замысел: разница между плечами смешалась
бы с разницей между машинами — другая карта, другой драйвер, другие ядра
cuDNN. Сравнение всегда идёт внутри одной пары, то есть внутри одной машины,
и разница машин сокращается.

**Пары идут вперемежку, а не блоками.** За 16 часов машина прогревается и
обрастает состоянием. Если бы сначала шли все контроли, а потом все плечи,
любой такой дрейф записался бы в счёт гипотезы.

**Сиды не пересекаются между машинами** (101–106 и 201–206) и не совпадают с
уже использованными 42 и 7 — иначе пары были бы не независимы.

**Валидация одна на всех.** `data.val_seed: 42` константен и отделён от
`seed`, так что все 24 прогона меряются на одних и тех же 5025 позитивах и 639
негативах. Это то самое, на чём споткнулся `f1-seed7`: у него подвыборка
позитивов бралась глобальным сидом, и с `f0` совпало 1892 кадра из 5664.
`scripts/seed_sweep_report.py` всё равно выравнивает наборы по `stem` и ругается,
если они разъехались.

## Заморозка кода

Обе половины обязаны считаться на одном и том же коммите. Иначе разница между
машинами станет ещё и разницей между версиями кода.

```bash
git rev-parse HEAD
```

Этот хэш записать сюда перед стартом и на сервере делать `git checkout <хэш>`.
На время свипа не трогать: `engine.py`, `losses.py`, `models/`, `datasets.py`,
`transforms.py`, `configs/_base.yaml`, `configs/_f_base.yaml`,
`configs/sw_*.yaml`. Правки в `analysis/`, `docs/` и тестах безопасны.

## Что положить на сервер

`scripts/setup_server.sh` разворачивает окружение и данные, но приватную часть
воркспейса не приносит. Скопировать руками:

```
configs/_base.yaml  configs/_f_base.yaml  configs/sw_control.yaml  configs/sw_aux.yaml
plans/sweep_seeds_server.yaml
artifacts/index.parquet  artifacts/folds.parquet
runs/f0-control-768/config.yaml
runs/f0-control-768/metrics.jsonl
runs/f0-control-768/summary.json
runs/f0-control-768/oof/val.npz          (3.9 МБ)
runs/f0-control-768/oof/val_rows.parquet
```

Последние четыре — для гейта из блока `stats`. Он не решает исход свипа, он
проверяет стенд: если на сервере собрался не тот torch или подъехали не те
данные, гейт скажет об этом на третьей эпохе первого прогона, а не через 16
часов. Без этой папки первый прогон упадёт сразу на загрузке эталона — это
тоже приемлемо, но лучше знать заранее.

## Запуск

Локально:

```bash
python cli.py plan sweep_seeds_local --dry-run
python cli.py plan sweep_seeds_local
```

На сервере:

```bash
python cli.py plan sweep_seeds_server --dry-run
tmux new -s sweep 'python cli.py plan sweep_seeds_server'
```

Очередь переживает падения: упавший прогон помечается `failed`, остальные идут
дальше, а перезапуск плана пропускает всё, у чего уже есть `summary.json`.

Когда серверная половина досчитает, забрать её `runs/sw-*` на рабочую машину —
достаточно `summary.json` и `oof/` из каждой папки.

## Чтение результата

```bash
python scripts/seed_sweep_report.py
```

Скрипт находит все пары `sw-f0-sNNN` и `sw-f7-sNNN`, считает разницу в общей
операционной точке и печатает таблицу по сидам плюс сводку:

```
пар: 12
средняя дельта: +0.0068   sd по парам: 0.0110   se: 0.0032
95% CI: [-0.0002, +0.0138]   t(11) = +2.14, p = 0.055
для сравнения, по тюненым точкам: +0.0118 (накрутка от подбора порогов +0.0050)

ЭФФЕКТ НЕ ПОДТВЕРЖДЁН: интервал накрывает ноль.
  Пар нужно примерно: 11 для шанса 50%, 21 для шанса 80% поймать эффект такого размера.
```

Отчёт можно снять и на неполном наборе: незавершённые пары просто
пропускаются, так что промежуточный взгляд после локальной половины ничего не
ломает — при условии, что решение принимается по полному набору.

## Побочный выход

Двенадцать контрольных прогонов на одном бюджете — это прямое измерение
`train_sigma`, которое сейчас взято по двум парам реплик и равно 0.008.
Стандартное отклонение `sw-f0-s*` по двенадцати сидам заменит эту оценку на
нормальную, и её надо будет вписать в `stats.train_sigma` во всех конфигах.
Это полезно независимо от того, чем кончится свип по f7.
